# Botux — بوت تداول تعليمي لـ Binance Spot (محاكاة أولاً)

> **تنبيه مهم.** هذا مشروع **تعليمي** وليس توصية استثمارية. لا يَعِد بأي ربح، ولا يصف أي إعداد أو استراتيجية
> بأنها آمنة أو مضمونة. التداول ينطوي على احتمال خسارة جزء كبير أو كل رأس المال.
> **الوضع الافتراضي والوحيد الذي يعمل دون إعداد إضافي هو المحاكاة (Paper Trading)**؛ لا تُرسَل أي أوامر حقيقية.

## ماذا يفعل المشروع؟

- يجلب بيانات سوق **عامة** من Binance Spot (دون أي مفاتيح) ويتحقق من سلامتها.
- يشغّل استراتيجية **مثالاً تعليمياً** (تقاطع متوسطين متحركين، شراء فقط) عبر واجهة قابلة للاستبدال.
- يمرّر كل قرار عبر **مدير المخاطر** (حجم الصفقة، سقوف التعرّض، حد الخسارة اليومية) ثم **مدير الأوامر**
  ثم **محاكٍ ورقي** يطبّق فلاتر المنصة والرسوم والانزلاق.
- يختبر الاستراتيجية تاريخياً (**باكتست**) مع رسوم وانزلاق وفصل بين بيانات التدريب والاختبار.
- يتضمن موصلاً حقيقياً لـ Binance Spot **مقفلاً بعدة حواجز** (انظر [docs/SECURITY.md](docs/SECURITY.md)).

## الحالة بصدق

| البند | الحالة |
|---|---|
| المحاكاة وبيانات السوق العامة | مُختبَرة فعلاً على بيانات Binance الحقيقية العامة |
| الباكتست | مُختبَر على سنتين من شموع BTCUSDT (انظر [docs/BACKTEST_EXAMPLE.md](docs/BACKTEST_EXAMPLE.md)) |
| الموصل الموقّع (حساب/أوامر) | **غير مجرَّب على المنصة الحقيقية**: بيئة البناء كانت محجوبة جغرافياً (HTTP 451). مُختبَر بنقل HTTP وهمي ومتّسق مع الوثائق الرسمية فقط |
| التداول الحقيقي | **معطّل**. تفعيله قرارك أنت بعد [قائمة الخطوات](docs/LIVE_TRADING_CHECKLIST.md) |
| الاستراتيجية | مثال تعليمي. في اختبارنا لم تتفوّق على الشراء والاحتفاظ |

## المتطلبات والتثبيت

- Python ≥ 3.11 (جُرِّب على 3.13) و[`uv`](https://docs.astral.sh/uv/).
- اعتمادية التشغيل الوحيدة: `httpx`. أدوات التطوير: `pytest`, `hypothesis`, `ruff`, `mypy`, `pytest-cov`.

```bash
git clone https://github.com/mado9423-spec/Botux && cd Botux
make install            # أو: uv sync --extra dev
make check              # تنسيق + أنواع + اختبارات (يجب أن تنجح كلها)
```

## الإعداد

الإعدادات **غير سرية** وتوضع في ملف TOML. الأسرار (مفاتيح API) لا توضع فيه أبداً — المحمّل يرفض أي حقل يشبه سراً.

```bash
cp config/botux.example.toml config/botux.toml   # ملف محلي مُتجاهَل في Git
uv run botux check-config                        # يتحقق ويعرض ملخصاً وحالة حاجز التداول الحقيقي
```

أهم القيم الافتراضية (محافِظة، ومعروضة كنقطة بداية لا كتوصية):

| الإعداد | القيمة | المعنى |
|---|---|---|
| `mode` | `"paper"` | محاكاة |
| `risk.risk_per_trade_pct` | `0.005` | الخسارة المقبولة عند ضرب وقف الخسارة = 0.5% من الرصيد |
| `risk.stop_loss_pct` | `0.02` | وقف خسارة برمجي 2% |
| `risk.max_order_notional` | `100` USDT | سقف الأمر الواحد |
| `risk.max_position_notional` / `max_total_exposure` | `200` / `300` USDT | سقف الرمز / سقف الإجمالي |
| `risk.max_daily_loss` | `20` USDT | عند بلوغها: لا دخول جديد حتى اليوم UTC التالي |
| `execution.fee_rate` / `slippage_bps` | `0.001` / `5` | **افتراضات** للمحاكاة؛ طابِقها مع فئة رسوم حسابك |
| `paper.starting_balance` | `1000` USDT | رصيد المحاكاة |

> القيم العشرية تُكتب كنص (`"0.005"`) لتجنّب أخطاء الفاصلة العائمة؛ الأعداد العشرية الحرّة مرفوضة.

## التشغيل في المحاكاة

```bash
uv run botux paper                       # حلقة المحاكاة (Ctrl+C للإيقاف الآمن)
uv run botux paper --max-cycles 3        # دورات قليلة للتجربة
uv run botux status                      # حالة الإيقاف الطارئ والأوامر
```

- عند البدء ينتظر البوت **إغلاق الشمعة التالية** قبل أي قرار (بدء دافئ)، فلا يتصرف على إشارة قديمة.
  للتجربة فقط: `--act-on-current-candle`.
- رصيد المحاكاة في الذاكرة؛ كل تشغيل جديد يبدأ من الرصيد الابتدائي (السجل يبقى في قاعدة البيانات).
- المحاكاة تستخدم **طلبات GET عامة فقط**. لا توقيع، لا مفاتيح، لا أوامر — وهذا مثبت باختبارات
  ([tests/test_no_real_orders.py](tests/test_no_real_orders.py)).

## الإيقاف

| الطريقة | الأثر |
|---|---|
| `Ctrl+C` / `SIGTERM` | إيقاف لطيف: ينهي الدورة الجارية، يلغي الأوامر المفتوحة، ثم يخرج |
| `uv run botux kill --reason "..."` | **إيقاف طارئ** من أي طرفية: يلغي الأوامر المفتوحة ويتوقف؛ ويبيع الوضع المفتوح فقط إن كان `flatten_on_kill = true` |
| تكرار 5 أخطاء متتالية | يفعّل الإيقاف الطارئ تلقائياً مع تنبيه |
| `uv run botux unkill` | يزيل الإيقاف (قرار بشري؛ لا يزيله البوت بنفسه) |

> وقف الخسارة هنا **برمجي**: يعمل فقط والبوت يعمل ومتصل. الانزلاق السعري، الفجوات، انقطاع الشبكة أو توقف
> البوت قد تسبب خسارة أكبر من مسافة الوقف. ليس حماية مضمونة.

## الباكتست

```bash
uv run botux backtest --days 730 --interval 1h          # يجلب البيانات العامة ويطبع تقريراً
uv run botux backtest --data data/cache/BTCUSDT_1h.csv  # من ملف CSV محفوظ (fetch-data / --save)
```

يختار البارامترات على **بيانات التدريب فقط** (أول 70%) ويقيّم الاختيار **مرة واحدة** على بيانات الاختبار اللاحقة،
مع رسوم وانزلاق وتنفيذ عند افتتاح الشمعة التالية (بلا نظر للمستقبل). **حدوده:** رمز واحد، تقسيم واحد، فلاتر المنصة
الحالية لا التاريخية، لا عمق دفتر أوامر ولا تأخير ولا انقطاعات؛ والنتائج الجيدة قد تكون حظاً أو فرط تكيّف.

## استكشاف الأخطاء

| العَرَض | السبب والحل |
|---|---|
| `HTTP 451` / `GeoRestrictedError` | Binance لا تخدم موقعك/عنوانك. **لا يُتحايَل على هذا القيد.** استخدم بيئة يُسمح فيها بالخدمة (البيانات العامة عبر `data-api.binance.vision` قد تعمل رغم حجب `api.binance.com`) |
| `RateLimitError` (429) / `IPBannedError` (418) | يبدأ البوت فترة تهدئة تلقائية حسب `Retry-After` ولا يرسل شيئاً خلالها. خفّض الطلبات (`poll_seconds`) |
| `ClockSkewError` / `-1021` | ساعة الجهاز بعيدة عن الخادم؛ فعّل مزامنة NTP |
| `market data is stale` | آخر شمعة مغلقة قديمة (انقطاع/ساعة خاطئة). يتخطى البوت الدورة ويحسب الخطأ |
| `unresolved order(s)` / `Order LOST` | أمر غير مؤكد. لا يُعاد إرساله أبداً؛ راجع المنصة ثم `botux resolve-lost SYMBOL` |
| `config field ... looks like a secret` | وُضع مفتاح/سر في ملف الإعداد. انقله لمتغير بيئة (`.env.example`) |
| `live trading refused: ...` | حاجز التداول الحقيقي مغلق (المطلوب). يسرد كل شرط ناقص |
| `kill switch is set` | وُجد ملف الإيقاف (`.botux/KILL`)؛ أزِله بـ `botux unkill` بعد معالجة السبب |

## الانتقال إلى التداول الحقيقي

**غير مفعّل ولا يُفعَّل تلقائياً.** المطلوب منك أولاً: قراءة [docs/LIVE_TRADING_CHECKLIST.md](docs/LIVE_TRADING_CHECKLIST.md)
واتخاذ القرارات المدرجة فيها. مجرد وجود مفاتيح في البيئة **لا** يكفي ولا تُقرأ أصلاً في وضع المحاكاة.
