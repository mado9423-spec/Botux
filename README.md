# Botux — بوت تداول تعليمي لـ Binance Spot (محاكاة أولاً)

> **تنبيه مهم.** هذا مشروع **تعليمي** وليس توصية استثمارية. لا يَعِد بأي ربح، ولا يصف أي إعداد أو استراتيجية أو حد مخاطرة
> بأنه آمن أو مضمون. التداول ينطوي على احتمال خسارة جزء كبير أو كل رأس المال.
> **الوضع الافتراضي والوحيد الذي يعمل دون إعداد إضافي هو المحاكاة (Paper Trading)**؛ لا تُرسَل أي أوامر حقيقية، ولا تُقرأ أي مفاتيح.

## ماذا يفعل المشروع؟

- يجلب بيانات سوق **عامة** من Binance Spot (دون مفاتيح) ويتحقق من سلامتها (تكرار، ثغرات، ترتيب، شمعة غير مغلقة، بيانات قديمة).
- يشغّل استراتيجية **مثالاً تعليمياً** (تقاطع متوسطين متحركين، شراء فقط) عبر واجهة قابلة للاستبدال.
- يمرّر كل قرار عبر **دفتر رأس مال البوت** و**مدير المخاطر** (حجم الصفقة، سقوف التعرّض، حد الخسارة اليومية) ثم **مدير الأوامر**
  ثم **محاكٍ ورقي** يطبّق فلاتر المنصة والرسوم والانزلاق.
- يختبر الاستراتيجية تاريخياً (**باكتست**): تدريب ← تحقق ← اختبار، وwalk‑forward، مع رسوم وانزلاق وأساس مقارنة عادل.
- يتضمن موصلاً حقيقياً لـ Binance Spot **مقفلاً بعدة حواجز** (انظر [docs/SECURITY.md](docs/SECURITY.md)) **لم يُشغَّل قط على المنصة الحقيقية**.

## الحالة بصدق

| البند | الحالة |
|---|---|
| المحاكاة وبيانات السوق العامة | مُختبَرة فعلاً على بيانات Binance الحقيقية العامة (`data-api.binance.vision`) |
| الباكتست | مُختبَر على سنتين من شموع BTCUSDT: [docs/BACKTEST_EXAMPLE.md](docs/BACKTEST_EXAMPLE.md) — **لا دليل على ميزة** (النتائج تتبدّل بين الشرائح) |
| الموصل الموقّع (حساب/أوامر) | **غير مجرَّب على المنصة الحقيقية**: `api.binance.com` و`testnet.binance.vision` يعيدان **HTTP 451** من بيئة البناء (قيد جغرافي لا يُتحايَل عليه). مُختبَر بنقل HTTP وهمي ومحاكٍ حالتي (stateful) متّسق مع الوثائق الرسمية فقط |
| Spot Testnet | **غير مدعوم وغير مُختبَر** (لا `/sapi` على Testnet ⇒ بوابة المشروع تفشل مغلقة؛ وهو محجوب هنا أيضاً): [docs/MODES.md](docs/MODES.md) |
| `order/test` | واجهة جاهزة (`botux live-check`) **لم تُشغَّل قط** على المنصة؛ وحتى نجاحها لا يثبت تنفيذاً |
| التداول الحقيقي | **معطّل**. تفعيله قرارك أنت بعد [قائمة الخطوات](docs/LIVE_TRADING_CHECKLIST.md) |
| الاستراتيجية | مثال تعليمي. لا ميزة مؤكدة في اختباراتنا، وعدد الصفقات قليل إحصائياً |
| مفاتيح HMAC | وثائق Binance (2026) تصفها بـ**المهجورة** وتوصي بـ Ed25519؛ الموصل يدعم HMAC فقط (دعم Ed25519 يتطلب اعتمادية تشفير جديدة — قرارك) |

أرقام آخر تشغيل فعلي: انظر [docs/VERIFICATION.md](docs/VERIFICATION.md) (الأوامر والنتائج بالأرقام).

## المتطلبات والتثبيت

- Python ≥ 3.11 (جُرِّب على 3.13) و[`uv`](https://docs.astral.sh/uv/).
- اعتمادية التشغيل الوحيدة: `httpx`. أدوات التطوير: `pytest`, `hypothesis`, `ruff`, `mypy`, `pytest-cov`.

```bash
git clone https://github.com/mado9423-spec/Botux && cd Botux
make install            # أو: uv sync --extra dev
make check              # تنسيق + أنواع + اختبارات (يجب أن تنجح كلها)
```

## الإعداد

الإعدادات **غير سرية** وتوضع في ملف TOML. الأسرار (مفاتيح API) لا توضع فيه أبداً — المحمّل يرفض أي حقل يشبه سراً.

```bash
cp config/botux.example.toml config/botux.toml   # ملف محلي مُتجاهَل في Git
uv run botux check-config                        # يتحقق ويعرض ملخصاً وحالة حاجز التداول الحقيقي
```

أهم القيم الافتراضية (معروضة كنقطة بداية **لا كتوصية**، وأخطارها مذكورة):

| الإعداد | القيمة | المعنى والخطر |
|---|---|---|
| `mode` | `"paper"` | محاكاة |
| `risk.bot_capital` | غير مضبوط | المبلغ الذي يعدّه البوت **رأس ماله هو**. في المحاكاة: كامل الرصيد الوهمي. في الحقيقي: **إلزامي بلا افتراضي** (قرارك) — لا يُستعمل رصيد الحساب كله أبداً |
| `risk.risk_per_trade_pct` | `0.005` | الخسارة المقبولة عند ضرب وقف الخسارة = 0.5% من **رأس مال البوت** |
| `risk.stop_loss_pct` | `0.02` | وقف خسارة **برمجي** 2% (انظر القيود أدناه) |
| `risk.max_order_notional` | `100` USDT | سقف الأمر الواحد، مقيس عند **أسوأ سعر تنفيذ متوقع** (ask + الانزلاق المنمذج) |
| `risk.max_position_notional` / `max_total_exposure` | `200` / `300` | سقف الرمز / سقف الإجمالي |
| `risk.max_daily_loss` | `20` USDT | عند بلوغها: **لا دخول جديد حتى تُعيد الضبط يدوياً** `botux reset-daily-loss` (لا ينتهي بمنتصف الليل) |
| `risk.max_spread_pct` | `0.005` | لا دخول جديد إذا اتسع الفارق (ask−bid)/mid أكثر من ذلك |
| `execution.fee_rate` / `slippage_bps` | `0.001` / `5` | **افتراضات** للمحاكاة والباكتست؛ طابِقها مع فئة رسوم حسابك |
| `market.poll_seconds` | `30` | فترة الدورة (إيقاع ثابت؛ الوقف البرمجي يُفحص مرة كل دورة) |
| `market.rules_refresh_hours` | `6` | إعادة قراءة `exchangeInfo` (الفلاتر وحالة الرمز) |
| `paper.starting_balance` | `1000` USDT | رصيد المحاكاة |

> القيم العشرية تُكتب كنص (`"0.005"`) لتجنّب أخطاء الفاصلة العائمة؛ الأعداد العشرية الحرّة مرفوضة. القيم السالبة أو غير المنطقية
> (مثلاً `max_daily_loss ≥ bot_capital`، أو مضيف بيانات وتداول من بيئتين مختلفتين) تُرفض عند التحميل.

## التشغيل في المحاكاة

```bash
uv run botux paper                       # حلقة المحاكاة (Ctrl+C للإيقاف الآمن)
uv run botux paper --max-cycles 3        # دورات قليلة للتجربة
uv run botux status                      # الإيقاف الطارئ، الأوامر المعلّقة، وأسباب حجب الدخول
```

- **كل تشغيل** يبدأ بتسخين: يسجّل أحدث شمعة مغلقة ولا **يدخل** إلا بعد إغلاق شمعة **جديدة** (حتى بعد إعادة التشغيل)، فلا يعمل على إشارة دخول قديمة؛ أما **الخروج** المعلّق لمركز قائم فيُنفَّذ فوراً.
  والدخول لا يُنفَّذ إلا في أول نصف فاصل (10 دقائق كحد أقصى) بعد إغلاق الشمعة.
- رصيد المحاكاة في الذاكرة؛ كل تشغيل جديد يبدأ من الرصيد الابتدائي (السجل يبقى في قاعدة البيانات).
- **لكل وضع قاعدة بيانات مستقلة** (`data/botux-paper.sqlite3` و`data/botux-live.sqlite3`) ويرفض البوت فتح قاعدة وضعٍ بالوضع الآخر، فلا تستطيع المحاكاة مسح حالة تداول حقيقي. ونسخة واحدة فقط من البوت لكل قاعدة (قفل `flock`).
- المحاكاة تستخدم **طلبات GET عامة فقط**. لا توقيع، لا مفاتيح، لا أوامر — وهذا مثبت باختبارات
  ([tests/test_no_real_orders.py](tests/test_no_real_orders.py)). الفروق بين المحاكاة والواقع: [docs/MODES.md](docs/MODES.md).

## ما يملكه البوت وما لا يلمسه

البوت لا يعدّ الحساب كله ماله. رأس ماله = `risk.bot_capital` + نتيجة **تنفيذاته المسجّلة هو** (دفتر محلي، `src/botux/ledger.py`). ولذلك:
- الحجم والتعرّض وحد الخسارة اليومية تُحسب على دفتر البوت، لا على رصيد الحساب (إيداع/سحب/عملات قديمة لا تحرّكها).
- عملة الأساس لا تُباع إلا إن شرحتها **تنفيذاته هو**؛ ورصيدك السابق (خط أساس) وأوامرك أنت لا تُمَسّ.
- أي فرق غير مفسَّر (إيداع، سحب، صفقة يدوية، تنفيذ غير مسجَّل) أو **أمر مفتوح لم يضعه البوت** ⇒ **يتوقف الدخول الجديد** وينبّه بحرج؛
  لا شيء يُباع أو يُلغى تلقائياً. بعد أن تتحقق على المنصة: `botux ack-balances --confirm-checked`.
  تحذير صريح: إن كان البوت يحمل مركزاً لا يستطيع إثبات ملكيته (مثلاً بعت أنت عملتك القديمة) فهو **غير مغطى بوقف الخسارة** حتى تقرّ.
- يُنصح (ولا يُفرض) بـ **حساب فرعي مخصص** للتشغيل الحقيقي: عزل البرمجيات وحده لا يحمي بقية أصولك.

## الإيقاف

| الطريقة | الأثر |
|---|---|
| `Ctrl+C` / `SIGTERM` | إيقاف لطيف: ينهي الدورة الجارية، يلغي أوامره المفتوحة (المعروفة له فقط)، ثم يخرج |
| `uv run botux kill --reason "..."` | **إيقاف طارئ**: ينشئ ملف الإيقاف (المسار المطلق يُطبع، ويفشل الأمر بصوت عالٍ إن تعذّرت كتابته). يسوّي البوت ما في الطريق، يلغي أوامره المفتوحة، **لا يرسل أي بيع** (حتى وقف الخسارة) إلا إن كان `flatten_on_kill = true`، ثم يتوقف وينبّه إن بقي مركز أو أمر غير محسوم |
| تكرار 5 أخطاء دورة متتالية | يفعّل الإيقاف الطارئ تلقائياً مع تنبيه. (مشكلة شموع/سعر رمز غير محمول لا تُحتسب: انظر `no_signal` في السجل) |
| `uv run botux unkill` | يزيل الإيقاف (قرار بشري؛ لا يزيله البوت بنفسه) |
| `uv run botux disarm-live` | يلغي التسليح: البوت العامل يوقف **الدخول الجديد** لكنه يواصل الخروج (وقف خسارة/إخراج استراتيجية)؛ للإيقاف الكامل استخدم `kill` |

> **وقف الخسارة هنا برمجي** ويُفحص مرة كل دورة (فترة `poll_seconds` بإيقاع ثابت، ويطول إن طالت الدورة نفسها بسبب إعادات الاتصال):
> يعمل فقط والبوت يعمل ومتصل بالسعر وقاعدة البيانات قابلة للكتابة. الانزلاق والفجوات وانقطاع الشبكة وتوقف البوت وتعذّر الكتابة
> في قاعدة البيانات (الكتابة المسبقة شرط لأي أمر، الخروج منه) قد تسبب خسارة أكبر من مسافة الوقف. **ليس حماية مضمونة.**

## الباكتست

```bash
uv run botux backtest --days 730 --interval 1h          # يجلب البيانات العامة ويطبع تقريراً
uv run botux backtest --data data/cache/BTCUSDT_1h.csv  # من ملف CSV محفوظ (fetch-data / --save)
uv run botux backtest --data ... --walk-forward         # اختيار على الماضي ثم حكم على النافذة التالية (5 نوافذ)
```

تقسيم **زمني** إلى تدريب (50%) ← تحقق (20%) ← اختبار (30%): الشبكة كلها على التدريب فقط، أفضل 3 تنتقل للتحقق ويُختار الفائز هناك،
والاختبار يُقيَّم **مرة واحدة** ولا يُضبط عليه شيء. تنفيذ عند افتتاح الشمعة التالية (بلا نظر للمستقبل)، رسوم وانزلاق، قرار يُسقَط إن عبر ثغرة
في البيانات. يعرض: العائد الصافي، أقصى تراجع، عدد الصفقات، التعرّض، الرسوم، الفترة (UTC)، وخطّي أساس **على نفس رأس المال المُوظَّف فعلاً**
(ومعدَّلاً لنفس زمن التعرّض) — لا مقارنة بشراء كامل الرصيد. **حدوده:** رمز واحد، فلاتر المنصة الحالية لا التاريخية، لا عمق دفتر ولا تأخير ولا
انقطاعات ولا تنفيذ جزئي؛ والنتائج الجيدة قد تكون حظاً أو فرط تكيّف، وقلة الصفقات أو عدم استقرار الاختيار لا تثبت شيئاً.

## استكشاف الأخطاء

| العَرَض | السبب والحل |
|---|---|
| `HTTP 451` / `GeoRestrictedError` | Binance لا تخدم موقعك/عنوانك. **لا يُتحايَل على هذا القيد.** استخدم بيئة يُسمح فيها بالخدمة (البيانات العامة عبر `data-api.binance.vision` قد تعمل رغم حجب `api.binance.com`) |
| `RateLimitError` (429) / `IPBannedError` (418) | يبدأ البوت فترة تهدئة تلقائية حسب `Retry-After` ولا يرسل شيئاً خلالها. خفّض الطلبات (`poll_seconds`) |
| `ClockSkewError` / `-1021` | ساعة الجهاز بعيدة عن الخادم؛ فعّل مزامنة NTP |
| `No usable market data` / `no_signal` | ثغرة/قِدَم في الشموع: لا إشارات الآن، ووقف الخسارة يعمل. يزول بزوال المشكلة |
| `Unexpected balance change` / `Foreign open order` | فرق غير مفسَّر أو أمر ليس من البوت: لا دخول جديد. تحقق على المنصة ثم `ack-balances` |
| `Daily loss limit reached` | الحجب لا ينتهي وحده: افهم السبب ثم `reset-daily-loss --confirm-checked` |
| `unresolved order(s)` / `Order LOST` | أمر غير مؤكد. لا يُعاد إرساله أبداً (والبيع الضائع يحجب بيعاً آخر)؛ راجع المنصة ثم `botux resolve-lost SYMBOL` |
| `config field ... looks like a secret` | وُضع مفتاح/سر في ملف الإعداد. انقله لمتغير بيئة (`.env.example`) |
| `live trading refused: ...` | حاجز التداول الحقيقي مغلق (المطلوب). يسرد كل شرط ناقص (ومنه `risk.bot_capital`) |
| `settings changed on disk since this process started` | عُدّل ملف الإعداد أثناء التشغيل: الدخول الجديد مغلق؛ أعد التشغيل (وأعد التسليح) |
| `kill switch is set` | وُجد ملف الإيقاف (`.botux/KILL`)؛ أزِله بـ `botux unkill` بعد معالجة السبب |
| `another Botux instance is already using ...` | نسخة أخرى تعمل على نفس قاعدة البيانات؛ أوقفها أولاً |
| `this database belongs to 'live' mode ...` أو `... a different Binance account` | قاعدة كل وضع وكل حساب مستقلة؛ أعطِ كل منهما `paths.database` خاصاً |

## الانتقال إلى التداول الحقيقي

**غير مفعّل ولا يُفعَّل تلقائياً.** المطلوب منك أولاً: قراءة [docs/LIVE_TRADING_CHECKLIST.md](docs/LIVE_TRADING_CHECKLIST.md) واتخاذ القرارات المدرجة
فيها. مجرد وجود مفاتيح في البيئة **لا** يكفي ولا تُقرأ أصلاً في وضع المحاكاة. والمنصة والاختصاص القانوني (هل Binance.com هي المناسبة لبلد تشغيلك؟)
**قرارك أنت** — لم أفترض تحويلاً إلى منصة أخرى.
