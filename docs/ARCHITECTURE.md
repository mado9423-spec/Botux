# المعمارية

## فصل المسؤوليات

```
                 ┌────────────── بيانات السوق العامة (GET فقط) ──────────────┐
                 │  data/market.py: جلب + تحقق (تكرار/ثغرات/OHLC/قِدَم)        │
                 └───────────────────────────────┬──────────────────────────┘
                                                 ▼
 strategy/  ──►  runner.py (الحلقة)  ──►  risk/manager.py  ──►  execution/order_manager.py
 (إشارة فقط)     دورة واحدة كل poll       حجم الصفقة + السقوف        كتابة مسبقة + معرّف حتمي + تسوية
                       │                                                    │
                       │                                       ┌────────────┴────────────┐
                       ▼                                       ▼                         ▼
              killswitch / alerts / storage          execution/paper.py        execution/live.py
                                                     (محاكٍ بلا شبكة)          (مقفل بحاجز safety.py)
                                                                                         │
                                                                              exchange/client.py (قائمة بيضاء)
```

| المكوّن | الملف | مسؤوليته الوحيدة |
|---|---|---|
| بيانات السوق | `data/market.py` | تحويل الشموع إلى `Decimal` والتحقق منها؛ إسقاط الشمعة غير المغلقة؛ اكتشاف البيانات القديمة |
| الاستراتيجية | `strategy/*` | `on_candles(شموع مغلقة، هل في مركز؟) → إشارة`. لا تعرف المال ولا الأوامر |
| المخاطر | `risk/manager.py` | حساب الكمية (تقريب للأسفل دائماً)، السقوف، حد الخسارة اليومية، البوابة الأخيرة قبل الأمر |
| قواعد المنصة | `exchange/rules.py` | تحليل `exchangeInfo`، تقريب السعر/الكمية، التحقق من PRICE_FILTER/LOT_SIZE/MARKET_LOT_SIZE/NOTIONAL/PERCENT_PRICE |
| مدير الأوامر | `execution/order_manager.py` | الإرسال المتكرر-الآمن، حالات الأمر، التسوية، منع التكرار |
| المحاكي | `execution/paper.py` | تنفيذ وهمي بنفس فلاتر المنصة والرسوم والانزلاق؛ حقن أعطال للاختبار |
| الموصل | `exchange/client.py` | HTTP + التوقيع + حدود الطلبات + قائمة النقاط المسموحة |
| الحاجز | `safety.py` | شروط التفعيل الحقيقي وفحص صلاحيات المفتاح |
| الإيقاف | `killswitch.py` | ملف + علم في الذاكرة؛ لا يُزال تلقائياً |
| التخزين | `storage.py` | SQLite: أوامر، تنفيذات، أحداث، حالة، منحنى رأس المال |
| الحلقة | `runner.py` | تنسيق الدورة وإدارة الأخطاء والإيقاف |

## دورة واحدة (`TradingLoop.run_cycle`)

1. هل الإيقاف الطارئ مفعّل؟ ← إلغاء الأوامر المفتوحة (وبيع المركز إن طُلب) ثم التوقف.
2. إعادة فحص حاجز التداول الحقيقي (حي فقط): إن أُغلق ← إيقاف الدخول الجديد + تنبيه حرج.
3. تسوية الأوامر غير المؤكدة/المفتوحة (`reconcile_pending`).
4. جلب أسعار العرض/الطلب؛ حساب رأس المال والمراكز؛ تحديث حد الخسارة اليومية؛ حفظ منحنى رأس المال والحالة.
5. **الحماية أولاً:** وقف الخسارة البرمجي لكل رمز، من السعر والأرصدة فقط **دون الاعتماد على الشموع**، ولا يمنعه أمر شراء
   غير محسوم (يمنعه فقط بيع غير محسوم، لتفادي البيع مرتين). الفشل في الخروج ينتج تنبيهاً حرجاً.
6. ثم الإشارات: جلب الشموع المغلقة والتحقق ← إن ظهرت شمعة **أحدث** من آخر معالَجة: إشارة ← حجم ← بوابة المخاطر ← أمر.
   صورة المحفظة تُعاد بناؤها بعد كل أمر؛ وفشل رمز لا يوقف بقية الرموز.
7. قرار واحد على الأكثر لكل شمعة، إلا الأوامر التي ثبت أنها لم تُرسل (لا اتصال/انحراف ساعة/حد طلبات) فتُعاد حتى 3 مرات.

## آلة حالات الأمر

```
            ┌──────────────► REJECTED   (رفض قطعي: لم يُنفَّذ)
 PENDING_SEND ──► NEW ──► PARTIALLY_FILLED ──► FILLED
      │                │                          CANCELED / EXPIRED
      └──► UNKNOWN ────┘   (مهلة/5XX/‎-1007: ربما نُفِّذ)
              │
              └─ استعلام بالمعرّف ─► يتبنّى حالة المنصة
              └─ لم يوجد بعد N محاولات ─► LOST (+تنبيه حرج، الرمز يبقى محجوباً حتى قرار بشري)
```

الأخطاء المفضية إلى `UNKNOWN`: مهلة، 5XX، ‎-1000/‎-1001/‎-1006/‎-1007/‎-1008، 408/499، أي استجابة بلا جسم Binance مفهوم (HTML من وسيط)،
200 غير قابلة للقراءة. أما `-1021` وحدود الطلبات وعدم الاتصال فتعني «لم يُرسل قطعاً» ← يُحذف السجل ويُعاد المحاولة لاحقاً.

ضمانات: الإدخال في قاعدة البيانات **قبل** الإرسال؛ `client_order_id` حتمي = `bx` + 30 خانة من SHA-256 لمفتاح النية
(استراتيجية:رمز:شمعة:اتجاه) فلا يتكرر الأمر عبر إعادة التشغيل؛ **لا إعادة إرسال تلقائية أبداً**؛ التنفيذات تُسجَّل مرة
واحدة مهما تكررت التسوية.

## لماذا الاستطلاع لا WebSocket؟

أبسط وأسهل في التحقق والاختبار ويكفي لشموع ≥ 15 دقيقة. الثمن: تأخر الاكتشاف بمقدار فترة الاستطلاع. تدفق بيانات المستخدم
(User Data Stream) تحسين مستقبلي لتقليل الاعتماد على الاستعلام.
